## 一、已确认的业务基线

WF-07 在当前会话中创建、查看、完成、延期、调整或取消学期任务。

固定规则：

1. 首次创建 3～5 个任务，覆盖最近四周，先形成 draft 并等待确认。
2. 查看已有 confirmed 时只在 reply 中摘要展示，不制造新草稿。
3. 完成任务必须明确任务并提供实际结果或证据；证据不足时追问，不能标记完成。
4. 延期必须明确任务、新日期或时间范围、延期原因；缺一项就追问。
5. 取消指定任务只改变任务状态，不删除任务记录。
6. 调整基于已有 confirmed 创建 draft，并保留未被点名的任务。
7. 所有正式任务变更都先进入 draft 和 `awaiting_confirmation`，确认后才复制到 confirmed。
8. `task_id` 在当前状态中唯一。
9. 不得声称已写入日历或发送提醒。

## 二、上游信息优先级与边界

| 优先级 | 数据来源 | 处理方式 |
|---:|---|---|
| 1 | WF-06 `plan_confirmed` | 根据已确认主规划生成任务 |
| 2 | WF-01 `profile_confirmed` | 没有主规划时生成临时任务清单，并明确提醒其临时性质 |
| 3 | 两者均为空 | 询问用户目标，或仅生成谨慎的临时清单；不得编造画像、规划或截止日期 |

WF-06 和 WF-01 都是可选增强信息，不是进入 WF-07 的硬门槛。不得修改任何上游 confirmed 数据，也不得因上游缺失强制退回其他模块。

## 三、已确认的状态机与动作语义

### 模块状态

统一使用：

- `not_started`
- `collecting`
- `awaiting_confirmation`
- `complete`
- `cancelled`
- `clarification_needed`

### 单个任务状态

严格使用 confirmed 业务结构中的中文枚举：

- `待处理`
- `完成`
- `推迟`
- `取消`

### 原提示词歧义的固定解释

1. “查看”已有 confirmed 后，模块 `current_status` 和 `task_status` 使用英文 `complete`，不是中文“完成”。
2. 原文“取消指定任务状态改为 cancelled”按 confirmed 业务结构解释为单个任务状态 `取消`；模块整体取消才使用 `cancelled`。
3. 原文“基于 confirm 创建 draft”解释为基于已有 `confirmed` 创建修订草稿。
4. “取消当前草稿”和“取消指定任务”必须区分：前者清空 draft；后者创建任务变更草稿，等待确认。
5. 没有可确认草稿时，confirm 不得完成模块。

## 四、draft 与 confirmed 业务结构基线

```json
{
  "学期":"",
  "任务":[
    {
      "task_id":"T01",
      "任务":"",
      "优先级":"高|中|低",
      "截止日期":"",
      "状态":"待处理|完成|推迟|取消",
      "success_criteria":[],
      "expected_evidence":[],
      "actual_evidence":[],
      "delay_reason":""
    }
  ],
  "weekly_focus":[],
  "摘要":""
}
```

固定约束：

- 首次生成 3～5 个任务；状态容量上限仍为 10 个任务。
- 普通数组最多 5 项，warnings 最多 3 项。
- task_id 必须非空且在同一对象中唯一。
- 完成任务时 `actual_evidence` 必须非空。
- 推迟任务时新截止日期或时间范围与 `delay_reason` 必须同时存在。
- 未被用户点名的任务必须保留。
- 不保存冗长分析、面向用户的完整回复或知识库原文。

## 六、WF-07 模块表字段基线

建议表名：`wf07_semester_task_records`

| 字段 | 类型 | 默认值 | 用途 |
|---|---|---|---|
| `task_status` | String | `not_started` | WF-07 当前模块状态 |
| `task_draft` | String | `{}` | 收集或待确认的任务对象 |
| `task_confirmed` | String | `{}` | 用户已确认的任务对象 |
| `task_version` | Integer | `1` | 模块记录版本 |
| `last_user_intent` | String | `未记录` | 用户本轮原话 |
| `warnings` | String | `[]` | 本模块警告数组的 JSON 字符串 |

六个字段是后续读取、初始化、统一重新读取、大模型输入、C01 输出和模块写回的固定合同。任务数组及其全部属性都保存在 draft 或 confirmed JSON 中，不为 task_id、证据、截止日期、延期原因等另加数据库列。

回复不写数据库，继续通过共享 `last_reply`、现有 N90 和唯一结束节点返回。

当前状态：业务基线、上游边界、状态机、业务结构和六字段模块表已经讨论确认并归档；讯飞星辰平台尚未实际建表。
