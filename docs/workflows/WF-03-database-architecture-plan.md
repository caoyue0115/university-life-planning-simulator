## 一、已确认的业务基线

WF-03 通过三道固定顺序、没有明显标准答案的场景题，采集五路径信号和八项能力信号。

题目顺序：

1. 期末考试前一周的时间与压力安排。
2. 导师项目、比赛和实习发生冲突。
3. 稳定目标与高不确定机会之间的选择。

第三题后生成主路径信号、备选路径信号、优势、弱点、待验证假设和摘要，进入待确认状态。结果必须说明：这是行为倾向信号，不是人格或职业定论。

当前大模型节点已确认：

- 输入：`user_input`、`router_context`。
- 输出：`output`，类型为 String。
- 数据库化后仍保留单一 String 输出形式。

### 第 1 个节点：`WF03_DB01_读取画像状态`

#### 连线

```text
M03 MAIN 总分支器的 WF-03 出口
→ WF03_DB01_读取画像状态
```

#### 节点配置

| 设置项 | 配置 |
|---|---|
| 节点类型 | 数据库 |
| 模式 | 表单处理数据 |
| 数据表 | `university_planner / wf01_profile_records` |
| 处理模式 | 查询数据 |
| 查询上限 | `1` |
| 排序 | 留空 |
| 输出 | 保持默认的 `isSuccess`、`message`、`outputList` |

#### 设置数据范围

| 表字段 | 条件 | 值类型 | 比较值 |
|---|---|---|---|
| `profile_version` | 大于 | 输入 | `0` |

#### 查询结果字段

- `profile_status`
- `profile_confirmed`
- `profile_version`

当前不读取 `profile_draft`，因为未确认画像不能作为可靠事实。

#### 逻辑边界

1. 有可解析的非空 `profile_confirmed` 时，WF-03 可用它适度个性化题目，但不得改写画像。
2. 没有画像、画像为空或无法解析时，WF-03 仍使用中性通用场景开始。
3. `profile_version > 0` 只表示画像记录已经初始化，不表示画像已经确认。
4. 本节点之后不得设置“无画像退回 WF-01”的拦截分支。

### 第 2 个节点：`WF03_DB02_读取冒险状态`

| 设置项 | 配置 |
|---|---|
| 节点类型 | 数据库 |
| 模式 | 表单处理数据 |
| 数据表 | `university_planner / wf03_survival_adventure_records` |
| 处理模式 | 查询数据 |
| 查询上限 | `1` |
| 排序 | 留空 |
| 输出 | 保持默认的 `isSuccess`、`message`、`outputList` |

这张 WF-03 业务表目前仍是设计，当前阶段不要求在星辰平台实际创建；后续执行同学按最终冻结版本建表。

#### 设置数据范围

| 表字段 | 条件 | 值类型 | 比较值 |
|---|---|---|---|
| `adventure_version` | 大于 | 输入 | `0` |

#### 查询结果字段

- `adventure_status`
- `adventure_draft`
- `adventure_confirmed`
- `adventure_version`
- `last_user_intent`
- `warnings`

#### 业务作用

1. 首次进入时查询结果为空，后续分支器据此进入初始化路径。
2. 后续进入时读取上一轮题目、答案、路径信号、能力信号和当前状态。
3. 用户下一轮只回答选项编号时，大模型依靠 `adventure_draft` 找回上一轮问题。
4. 用户确认、修改或取消时，大模型依靠当前记录判断是否存在待处理草稿。

#### 禁止事项与易错点

1. `adventure_version > 0` 只表示记录已经初始化，不表示三道题已经完成。
2. 是否完成必须检查 `adventure_status` 和 `adventure_confirmed`。
3. 本节点必须选择“查询数据”，不能选择新增或更新。
4. 六个业务字段必须一次性选齐，不能遗漏 `last_user_intent` 或 `warnings` 后再中途返工。
5. 本节点只读取数据，不填写 draft 或 confirmed 的具体 JSON 内容。

- 星辰平台实际搭建：当前不作要求。
