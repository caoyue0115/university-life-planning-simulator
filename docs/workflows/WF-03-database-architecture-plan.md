## 一、已确认的业务基线

WF-03 通过三道固定顺序、没有明显标准答案的场景题，采集五路径信号和八项能力信号。

题目顺序：

1. 期末考试前一周的时间与压力安排。
2. 导师项目、比赛和实习发生冲突。
3. 稳定目标与高不确定机会之间的选择。

第三题后生成主路径信号、备选路径信号、优势、弱点、待验证假设和摘要，进入待确认状态。结果必须说明：这是行为倾向信号，不是人格或职业定论。

当前大模型节点已确认：

- 输入：`user_input`、`router_context`。
- 输出：`output`，类型为 String。
- 数据库化后仍保留单一 String 输出形式。

### 第 3 个节点：`WF03_冒险状态是否存在`

#### 连线

```text
WF03_DB02_读取冒险状态
→ WF03_冒险状态是否存在
```

两个出口预留如下：

```text
如果：已有记录
→ WF03_DB04_读取当前冒险状态

否则：没有记录
→ WF03_DB03_初始化冒险状态
```

DB03 和 DB04 属于后续节点，本步骤只确定名称和连接方向。

#### 分支器配置

| 设置项 | 配置 |
|---|---|
| 节点类型 | 分支器 |
| 引用变量 | `WF03_DB02_读取冒险状态.outputList` |
| 选择条件 | 长度大于 |
| 比较值类型 | 输入 |
| 比较值 | `0` |

#### 分支含义

| 出口 | 条件结果 | 含义 | 后续节点 |
|---|---|---|---|
| 如果 | `outputList` 长度大于 `0` | 当前用户已有 WF-03 记录 | `WF03_DB04_读取当前冒险状态` |
| 否则 | `outputList` 为空 | 当前用户首次进入 WF-03 | `WF03_DB03_初始化冒险状态` |

#### 业务作用

本节点只判断数据库记录是否存在，不判断用户是否完成三道题、是否有待确认草稿或是否已有确认结果。这些业务状态由后续大模型根据 `adventure_status`、`adventure_draft` 和 `adventure_confirmed` 判断。

#### 禁止事项与易错点

1. 条件必须是“长度大于 `0`”，不能写成等于 `0`。
2. 必须引用 DB02 的整个 `outputList`，不能引用其中某个业务字段。
3. “如果”代表已有记录，“否则”代表需要初始化，两个出口不能接反。
4. 两个出口后续都必须连接，不能留下悬空分支。
5. 不要在分支器中重复判断 `adventure_version > 0`；该条件已经用于 DB02 查询。

#### 数据库查询失败边界

当前节点按照 WF-01、WF-02 已跑通的结构，只做存在性判断。实际配置时仍需确认 DB02 查询失败后平台是否继续执行：

- 查询成功且结果为空：允许进入初始化。
- 查询失败：不能误当成“没有记录”并新增数据。

数据库失败保护在整条 WF-03 架构完成后统一核对，不在本存在性分支中加入未经确认的处理方式。

| 字段名 | 值类型 | 填写值 | 字段类型 |

#### 业务作用

1. 本节点必须选择新增数据，不能选择查询或更新。

4. `last_user_intent` 手动输入 `未记录`，不要输入两个引号。
5. 六个业务字段必须一次填齐。
6. 不得手动填写系统生成的 `uid`、`id` 或 `create_time`。
7. DB03 后不能直接连接大模型，必须先进入 DB04 重新读取。
