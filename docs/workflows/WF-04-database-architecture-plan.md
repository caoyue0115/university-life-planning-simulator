## 一、已确认的业务基线

WF-04 是“五路径推荐”模块，不是连续答题模块。它读取可用的已确认上游结果，一次性生成可解释的初步路径建议，然后等待用户确认、修改或取消。

必须完整生成且不得重复的五条路径：

1. 保研
2. 考研
3. 就业
4. 考公
5. 留学

每条路径包含匹配等级、证据、空档、优先行动、风险和需核验的官方渠道。不得输出录取率、成功率、薪资预测或伪精确分数；不得编造具体政策。

结果还必须包含：

- 一个主路径，但不能替用户做最终决定；
- 至少一个备选路径；
- 跨路径资产；
- 不确定性；
- 摘要。

## 二、上游信息使用边界

WF-04 的上游数据均为“可用则增强、缺失也继续”，不能构成入口硬门槛：

| 上游模块 | 可使用内容 | 使用规则 |
|---|---|---|
| WF-01 用户画像 | `profile_confirmed` | 有可解析的已确认画像时优先使用；不得修改画像 |
| WF-02 虚拟大学 | `simulation_confirmed` | 有可解析的已确认结果时可作为场景和取舍证据；缺失时继续 |
| WF-03 生存大冒险 | `adventure_confirmed` | 有可解析的已确认结果时可作为路径与能力信号；缺失时继续 |

固定规则：

1. 没有画像、画像为空或无法解析时，仍必须进入 WF-04 并基于现有证据和通用规划原则生成建议。
2. 缺少 WF-02 或 WF-03 结果时不得退回对应模块，也不得阻止 WF-04。
3. 证据只能来自可用的已确认上游结果；没有证据的判断必须写入不确定性。
4. 不得改写任何上游表中的 draft 或 confirmed。

## 三、已确认的状态机

| 动作 | 前置状态 | 处理结果 |
|---|---|---|
| `start` | 无待确认结果 | 生成五路径建议，进入 `awaiting_confirmation` |
| `confirm` | `awaiting_confirmation` 且 draft 非空 | draft 复制到 confirmed，清空 draft，模块状态变为 `complete`，按需加入 WF-04 完成标记，`next_workflow=WF-12` |
| `modify` | 存在待确认 draft | 按用户明确偏好重算，说明偏好变化与证据变化，不得为迎合用户删除风险，保持 `awaiting_confirmation` |
| `cancel` | 当前模块可取消 | 清空 draft、保留 confirmed，模块状态变为 `cancelled` |

没有可确认草稿时不得执行完成操作。

必须保留的两条警告：

- `本结果为情景模拟推演，仅供参考，不能替代真实院校政策、招录数据或官方咨询`
- `推免、考试、招录、申请等规则必须以最新官方信息为准`

## 五、WF-04 模块表字段基线

建议表名：`wf04_path_recommendation_records`

| 字段 | 类型 | 默认值 | 用途 |
|---|---|---|---|
| `recommendation_status` | String | `not_started` | WF-04 当前业务状态 |
| `recommendation_draft` | String | `{}` | 待确认的五路径推荐结果 |
| `recommendation_confirmed` | String | `{}` | 用户确认后的五路径推荐结果 |
| `recommendation_version` | Integer | `1` | 模块记录版本 |
| `last_user_intent` | String | `未记录` | 用户本轮原话 |
| `warnings` | String | `[]` | 本模块警告数组的 JSON 字符串 |

说明：draft、confirmed 和 warnings 的真实内容不是在建表时展开填写。大模型生成对象或数组，C01 将其压缩为 String，DB05 再写入对应字段。回复不写入数据库，仍通过共享会话变量 `last_reply`、现有 N90 和唯一结束节点返回。

## 六、预期主链路骨架

WF-04 需要依次读取可选上游信息和自身跨轮状态，再沿用已确认的数据库主导骨架：

```text
M03 MAIN 总分支器的 WF-04 出口
→ 读取 WF-01 已确认画像
→ 读取 WF-02 已确认模拟结果
→ 读取 WF-03 已确认冒险结果
→ 读取 WF-04 推荐状态
→ 判断记录是否存在
→ 必要时初始化
→ 统一重新读取 WF-04 当前状态
→ WF-04 大模型
→ C01 解析模型输出
→ 解析是否成功
→ DB05 更新 WF-04 模块表
→ C02 合并公共路由状态
→ DB06 更新公共路由表
→ 写入共享 last_reply
→ 现有 N90
→ 唯一结束节点
```

本节只冻结总体方向，不代表所有节点配置已经确认。后续仍按“一次一个节点、用户确认后立即归档推送”的方式推进。

| 设置项 | 配置 |
|---|---|
| 节点类型 | 数据库 |
| 模式 | 表单处理数据 |
| 数据库 | `university_planner` |
| 数据表 | `wf01_profile_records` |
| 处理模式 | 查询数据 |
| 查询上限 | `1` |
| 排序 | 留空 |
| 输出 | 保持默认的 `isSuccess`、`message`、`outputList` |

#### 设置数据范围

| 表字段 | 条件 | 值类型 | 比较值 |
|---|---|---|---|
| `profile_version` | 大于 | 输入 | `0` |

`profile_version > 0` 只表示当前用户存在画像记录，不表示画像已经确认。

#### 查询结果字段

- `profile_status`
- `profile_confirmed`
- `profile_version`

不读取 `profile_draft`，因为未确认草稿不能作为五路径推荐的可靠证据。

#### 业务作用

WF-04 优先使用可解析的非空 `profile_confirmed` 作为五路径推荐证据。没有画像、画像为空或无法解析时，后续 WF-04 大模型仍须继续生成基于通用规划原则的建议。

#### 禁止事项与易错点

1. 不得增加“没有画像就返回 WF-01”的分支。
2. 不得使用 `profile_version > 0` 判断画像已经确认。
3. 本节点只查询，不得填写或修改画像内容。
4. 数据表必须选择 WF-01 画像表，不能误选 WF-04 模块表。
5. 不得修改数据库节点的默认输出。
