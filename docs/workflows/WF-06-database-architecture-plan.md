## 一、已确认的业务基线

WF-06 把用户选定的路径转换成四层可执行计划：

```text
路径
→ 学期目标
→ 月度里程碑
→ 最近四周行动
```

主规划必须实际向用户展示：主路径和备选路径、本学期 3～4 个核心目标、关键里程碑、最近四周逐周行动、主要风险及应对措施，并在最后询问确认或修改。不能只回复“规划已经生成”或“等待确认”。

计划必须按年级适配：

- 大一：适应、探索、建立习惯；
- 大二：收敛 1～2 条路径并补核心能力；
- 大三：聚焦目标并建立备选；
- 大四：完成申请、求职、考试、毕业和成果整理。

success criteria 必须可观察；每个目标都要有资源、风险、替代方案和不做清单；最近四周只安排最小可执行行动。

## 二、上游信息优先级与边界

| 优先级 | 数据来源 | 处理方式 |
|---:|---|---|
| 1 | WF-04 `recommendation_confirmed` | 使用主路径和备选路径生成个性化规划 |
| 2 | WF-01 `profile_confirmed` | WF-04 为空时生成通用适应性规划，并在 warnings 说明缺少路径推荐结果 |
| 3 | 两者均为空 | 只能生成谨慎通用规划或请求目标信息，不能编造年级、专业或路径 |

固定规则：

1. WF-04 是优先输入，不是强制入口门槛。
2. WF-01 也不能成为进入 WF-06 的强制门槛。
3. 不得修改任何上游 confirmed 数据。
4. 用户明确想换路径时，进入 collecting；如有 WF-04 已确认结果则列出可选路径，否则询问用户目标，确认目标后再生成完整规划。

## 三、已确认的状态机

| 状态或动作 | 处理结果 |
|---|---|
| `collecting` | 用户想换路径但目标尚未确定，等待目标选择 |
| `awaiting_confirmation` | 完整规划已生成，等待确认或修改 |
| `confirm` | 仅在待确认且 draft 非空时复制 draft 到 confirmed、清空 draft、状态变为 `complete`、按需加入 WF-06、`next_workflow=WF-12` |
| `modify` | 基于现有 draft 或 confirmed 创建修订草稿，说明影响，不得偷偷覆盖 confirmed |
| `cancel` | 清空 draft、保留 confirmed，状态变为 `cancelled` |
| `clarification_needed` | 没有可确认或可修改内容，或缺少生成计划所需目标信息 |

## 四、draft 结构基线与原提示词解释

```json
{
  "selected_route":"",
  "alternative_route":"",
  "target_route":"",
  "planning_horizon":"",
  "semester_goals":[
    {
      "学期":"",
      "进球":"",
      "success_criteria":[],
      "monthly_milestones":[],
      "资源":[],
      "风险":[],
      "后备":[],
      "not_to_do":[]
    }
  ],
  "next_four_weeks":[
    {"week":1,"actions":[],"evidence":[]}
  ],
  "decision_points":[],
  "摘要":""
}
```

为保持原始字段合同并确保可实现，现阶段固定采用以下解释：

1. 保留历史键 `进球`，解释为“本学期核心目标”，不在未确认时擅自改名。
2. 原提示词要求保存的“里程碑”对应 `semester_goals[].monthly_milestones`。
3. 原提示词要求保存的“风险”对应 `semester_goals[].风险`。
4. `modify` 中“基于现有 draft 或 confirm”解释为“基于现有 draft 或 confirmed”，不把 confirm 动作当成数据对象。
5. 不新增重复的顶层“里程碑”或“风险”字段。

## 六、WF-06 模块表字段基线

建议表名：`wf06_main_plan_records`

| 字段 | 类型 | 默认值 | 用途 |
|---|---|---|---|
| `plan_status` | String | `not_started` | WF-06 当前业务状态 |
| `plan_draft` | String | `{}` | 收集中的路径选择或待确认主规划 |
| `plan_confirmed` | String | `{}` | 用户确认后的主规划 |
| `plan_version` | Integer | `1` | 模块记录版本 |
| `last_user_intent` | String | `未记录` | 用户本轮原话 |
| `warnings` | String | `[]` | 本模块警告数组的 JSON 字符串 |

这六个字段已经作为后续节点的固定合同。后续读取、初始化、重新读取、大模型输入、C01 输出和模块写回都必须使用同一组字段，不得中途增加遗漏字段。

draft、confirmed 和 warnings 的真实内容不是在建表时展开填写。大模型生成对象或数组，C01 序列化为 String，模块数据库更新节点再写入。回复不写数据库，继续通过共享 `last_reply`、现有 N90 和唯一结束节点返回。

当前状态：业务基线、上游优先级、状态机、结构解释和六字段模块表基线已经讨论确认并归档；讯飞星辰平台尚未实际建表。
